The ESLint rule "no-fallthrough" has two configurable options. Here are the details:

1. **Option Name**: commentPattern
   - **Option Description**: A regular expression string to change the test for intentional fallthrough comment. If the fallthrough comment matches a directive, that takes precedence over `commentPattern`.
   - **Data Type**: string
   - **Data Range**: open-ended
   - **Default Value**: no default

2. **Option Name**: allowEmptyCase
   - **Option Description**: Allows empty cases regardless of the layout. By default, this rule does not require a fallthrough comment after an empty `case` only if the empty `case` and the next `case` are on the same line or on consecutive lines.
   - **Data Type**: boolean
   - **Data Range**: {true, false}
   - **Default Value**: no default
